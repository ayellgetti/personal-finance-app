# Product Rules

## Product thinking

When evaluating a feature:

1. Identify the user problem.
2. Identify the target user.
3. Define the desired outcome.
4. Separate must-have from nice-to-have.
5. Identify edge cases.
6. Identify measurable success criteria.
7. Consider operational and technical implications.

## Requirements

Requirements should be:

- testable
- unambiguous
- prioritized
- independently understandable

Avoid vague requirements such as "make it better" unless the intended outcome is defined.

## User stories

Prefer:

> As a [user], I want [capability], so that [outcome].

Include acceptance criteria where useful.

## MVP

For MVP recommendations:

- optimize for learning and validated value
- avoid premature complexity
- identify dependencies
- explicitly list what is out of scope

## UX

Consider:

- first-time experience
- empty states
- loading states
- error states
- validation
- mobile/responsive behavior
- accessibility
- destructive actions
- recoverability

## Metrics

Prefer measurable metrics tied to user/business outcomes rather than vanity metrics.

## Product decisions

When recommending a product decision, state:

- recommendation
- rationale
- alternatives
- risks
- what would change the recommendation
